PARTIE I : FONDEMENTS THÉORIQUES — GIT ET AUTOMATISATION CI/CD

Comprendre la gestion de versions distribuée, les zones Git et le fonctionnement déclaratif de GitHub Actions.

1. Le contrôle de version avec Git

1.1 Qu'est-ce que Git ?

Git est un système de gestion de versions décentralisé (DVCS — Distributed Version Control System), créé en 2005 par Linus Torvalds pour gérer le développement du noyau Linux. Son rôle est d'enregistrer l'évolution d'un ensemble de fichiers au fil du temps afin de pouvoir :

  • Conserver un historique complet de chaque modification (qui a modifié quoi, quand et pourquoi).
  • Revenir à une version antérieure stable en cas de régression ou d'erreur critique.
  • Travailler en parallèle à plusieurs développeurs sur des fonctionnalités isolées (les branches) sans écraser le travail des autres.

Contrairement aux anciens systèmes centralisés (comme Subversion / SVN), Git est distribué : chaque développeur possède sur son poste une copie intégrale du dépôt et de tout son historique, garantissant l'intégrité cryptographique des données via des empreintes SHA-1.

Distinction fondamentale : Git vs GitHub
Git est le logiciel local exécuté en ligne de commande sur votre ordinateur qui gère le suivi des versions.
GitHub (tout comme GitLab ou Bitbucket) est une plateforme cloud hébergeant des dépôts Git distants, enrichie d'outils collaboratifs (Pull Requests, Issues) et d'automatisation (GitHub Actions).

1.2 Les zones de travail fondamentales de Git

ZoneEmplacementRôle technique
Répertoire de travail (Working Directory) Dossier du projet sur votre disque Contient les fichiers extraits d'une version du projet que vous êtes en train d'éditer.
Zone de transit / Index (Staging Area) Fichier interne dans .git/ Espace intermédiaire où vous préparez et sélectionnez précisément les modifications du prochain instantané.
Dépôt local (Local Repository) Sous-dossier caché .git/ Base de données locale stockant de façon permanente l'historique complet de tous vos commits et tags.
Dépôt distant (Remote Repository) Serveur externe (ex. GitHub) Version partagée du dépôt hébergée sur Internet, servant à la sauvegarde et à la synchronisation.

1.3 Commandes Git essentielles avec exemples

A. Configuration, initialisation et clonage :

git config --global user.name "Prenom Nom"
git config --global user.email "prenom.nom@exemple.com"
git config --global init.defaultBranch main

git init                                      # Initialise un dépôt neuf localement
git clone git@github.com:USER/DevOps_TP3.git  # Clone un dépôt distant existant

B. Suivi, instantanés et inspection :

git status                                    # État des fichiers (modifiés / indexés)
git add index.html style.css                  # Ajoute des fichiers à la zone de transit
git commit -m "feat: mise à jour du portail"  # Enregistre l'instantané dans l'historique
git diff                                      # Affiche les différences ligne par ligne
git log --oneline --graph --all --decorate    # Graphe visuel des branches et tags

C. Branches, fusions et tags :

git branch -a                                 # Liste les branches locales et distantes
git switch -c feature/ma-branche              # Crée et bascule sur une nouvelle branche
git switch main                               # Revient sur la branche principale
git merge --no-ff feature/monitoring-widget   # Fusionne avec un commit de merge explicite
git branch -d feature/ma-branche              # Supprime une branche déjà fusionnée
git tag -n                                    # Liste les tags annotés (ex. v1.0, v2.0)

D. Synchronisation distante & annulation :

git remote -v                                 # Affiche les dépôts distants configurés
git push -u origin main                       # Envoie main et mémorise le suivi
git pull origin main                          # Récupère et fusionne depuis origin/main
git restore index.html                        # Annule les modifications locales non commitées
git reset --hard origin/main                  # Réaligne strictement le dossier sur origin/main

2. L'automatisation CI/CD et GitHub Actions

2.1 Approche théorique de la CI/CD

  • Intégration Continue (CI — Continuous Integration) : À chaque git push, un pipeline vérifie automatiquement les sources (présence des fichiers, syntaxe HTML5/CSS3, tests) pour détecter les erreurs au plus tôt (Fail Fast).
  • Livraison Continue (Continuous Delivery) vs Déploiement Continu (CD — Continuous Deployment) : En livraison continue, l'artefact est prêt mais attend une validation humaine ; en déploiement continu, toute modification validée est mise en production automatiquement sans intervention manuelle.

2.2 Les 6 composants clés de GitHub Actions (Pipeline as Code)

Les workflows sont décrits en YAML dans .github/workflows/ :

  1. Workflow : Processus automatisé complet défini par un fichier .yml (ici .github/workflows/deploy.yml).
  2. Événement (on:) : Déclencheur du workflow (ex. push sur la branche main).
  3. Job : Ensemble d'étapes exécutées sur une même machine. Le mot-clé needs: impose un enchaînement séquentiel.
  4. Runner : Machine virtuelle éphémère hébergée par GitHub (ubuntu-latest) détruite après exécution.
  5. Step & Action : Opération unitaire exécutant une commande shell (run:) ou une action réutilisable (uses: actions/checkout@v4).
  6. Secrets (secrets.*) : Coffre-fort chiffré stockant les clés SSH, IP et chemins sensibles, masqués dans les logs.

Point critique de compatibilité des clés SSH : Générez vos clés SSH uniquement via Git Bash (ssh-keygen), au format standard OpenSSH (C:\Users\<Nom>\.ssh\id_ed25519). Une même clé fonctionne alors nativement avec GitHub, SmarTTY et GitHub Actions.

ÉTAPE 7 Analyse & Exécution du Pipeline CI/CD deploy.yml (25 min) GitHub

Le dépôt DevOps_TP3 inclut déjà le fichier .github/workflows/deploy.yml structuré en deux jobs séquentiels grâce à needs: ci-verification :

name: CI/CD - Portail DevOps TP 3

on:
  push:
    branches:
      - main

jobs:
  ci-verification:
    name: Vérification statique (HTML5 & CSS3)
    runs-on: ubuntu-latest
    steps:
      - name: Récupération du code source
        uses: actions/checkout@v4
      - name: Vérification de la présence des fichiers requis
        run: |
          test -f index.html && test -s index.html
          test -f style.css && test -s style.css
      - name: Contrôle basique de validité HTML5 et CSS3
        run: |
          grep -qi "<!DOCTYPE html>" index.html
          grep -qi "</html>" index.html
          grep -q 'href="style.css"' index.html
          grep -q "{" style.css && grep -q "}" style.css

  cd-deploiement:
    name: Déploiement SSH sur VPS Ubuntu (Apache 2)
    needs: ci-verification
    runs-on: ubuntu-latest
    steps:
      - name: Configuration de la clé SSH et déploiement sur le VPS
        env:
          VPS_SSH_KEY: ${{ secrets.VPS_SSH_KEY }}
          VPS_HOST: ${{ secrets.VPS_HOST }}
          VPS_USER: ${{ secrets.VPS_USER }}
          DEPLOY_PATH: ${{ secrets.DEPLOY_PATH }}
        run: |
          mkdir -p ~/.ssh && chmod 700 ~/.ssh
          printf '%s\n' "$VPS_SSH_KEY" > ~/.ssh/id_deploy
          chmod 600 ~/.ssh/id_deploy
          ssh-keyscan -H "$VPS_HOST" >> ~/.ssh/known_hosts
          ssh -i ~/.ssh/id_deploy "${VPS_USER}@${VPS_HOST}" "cd ${DEPLOY_PATH} && git pull origin main"
          rm -f ~/.ssh/id_deploy
